# 执掌东大 Android 版

Android 应用名为“执掌东大”，包名为 `cn.neu.zhizhangdongda`。

## 功能

- 登录页提供内置登录、学校原网页账密和二维码登录，默认选中内置登录；手机验证码作为内置登录面板中的补充入口；当学校已经登录但认证页没有自动跳转时，内置面板可手动打开教务系统原网页或关闭并返回主页，原网页登录模式的底部按钮也支持关闭认证页；
- 内置登录支持学号和密码；账密提交后学校可能整页换成设备二次认证（图形验证码 `#imgCode` 与短信 `#scendAuthCode`），旧版设备短信弹窗和手机模板也仍可能出现。这些人工验证都交给同一个可见的学校官方认证 WebView，不自动发送或重放验证码。默认勾选“信任此设备”：登录成功后用 Android Keystore AES-GCM 加密保存凭据；若官方页存在 `#saveDevice`（账密页上常为隐藏但仍可勾选）则同步当前选择，二次认证页没有该节点时保持跳过。教务会话失效时直接在不可见但持续运行的后台 WebView 使用加密凭据重登，后台会识别 HTML 登录页、JSON 登录失效和二次认证页，并在学校已写入可信设备 Cookie 但 URL 未跳转时直接探测教务接口确认成功；遇到人工验证会安全停止；E 码通会话失效时也会独立触发后台登录并只重载 E 码通页面。认证后若停在中转页会主动探测目标入口，恢复失败时在主页底部显示完整错误与其他登录入口；
- 登录失败诊断：后台或内置登录失败后可复制详细脱敏报告，包含运行环境、登录阶段、页面元数据、网络错误和事件时间线，不包含密码、验证码、Cookie 值、Token 或完整查询参数；
- 蓝色书本应用图标，Android 8.0 及以上使用自适应图标，同时提供旧系统兼容图层；
- 加载、后台登录、数据更新和导出状态使用底部导航上方的轻量提示，不挤动页面内容；设置页使用不受全局输入框样式影响的标准滑块关闭一般 Toast，偏好同时保存到 Android `SharedPreferences` 和页面状态，关闭后只显示缓存使用和数据刷新完成提示；需要用户处理的完整登录错误仍显示在手动登录入口旁；
- 设置页提供统一“当前学期”，可从教务系统同步或手动指定；总览、成绩、考试、个人课表、全校课表初始值和新建本地安排共用该设置。各查询页仍可单独切换历史学期且不会修改全局当前学期，偏好同时保存到 WebView 本地存储和 Android `SharedPreferences`；
- “更多工具”置于更多页首位，内置纯本地 WebVPN 地址生成器，可保留网址路径、查询参数和锚点，并在应用的学校页面 WebView 中直接访问生成结果；
- 首页当前/下一项和今天安排中的课程均可直接查看详情，页面切换时不会残留并在课表页延迟弹出；
- 所有模态弹窗打开时都会锁定并隐藏校园码，弹窗自身滚动与主页面顶部下拉手势隔离；关闭弹窗后保持隐藏，需在主页面重新顶部下拉才会显示；
- 设置页可直接打开自定义安排管理、编辑、冲突处理和安排详情；切换页面、点击弹窗遮罩或按 Android 返回键时统一清理弹窗状态，不会在之后进入课表页时延迟出现；
- 独立持久化教务系统 WebView Cookie/SSO 会话，下次启动复用教务登录状态；
- 进入首页后独立加载校园 E 码通官方原网页，默认以约 112dp 的紧凑卡片展示二维码缩略图和更新时间；缩略图优先按 DOM 二维码节点裁切，失败时按整页截图的高对比度方形区域分析兜底；卡片随课表页内滚动向下隐藏、向上或回到顶部显示，点击卡片可展开完整原网页；
- E 码通原网页支持单独登录和刷新，E 码通失效不会阻塞教务查询；
- 成绩详情、成绩分项、全学期累计 GPA；
- 按学号与查询学期隔离的新成绩弹窗提醒；首次查看历史学期只建立基线，不会集中误报；
- 考试日期、起止时间、场次、考场、座位和状态；
- 个人课表网格、课程详情和分周显示；同一门课程的多个星期、周次、节次或地点在课程主项下以排课子列表展示；
- 个人课表中的本地覆盖层：可添加重复课程或一次性日程，支持编辑、复制、停用、删除、冲突处理和按学期隔离；新建课程默认只安排今天和当前教学周，没有第一周日期时周次保持空白并允许直接填写，不会默认整学期；本地数据独立于教务缓存，不会回写学校系统；
- 个人课表网格、日视图、列表和详情均标出考试/考察与必修/选修；
- 课表图片导出：支持整个学期或指定周，导出图片使用节次 × 星期网格；同一格课程最多两列平铺，更多课程换到下一行，卡片不重叠，保存到“图片/执掌东大”；
- 课表 CSV 导出：个人课表和全校班级/教师/教室课表明细共用同一套排课记录映射，输出 UTF-8 BOM、全字段双引号和 WakeUp 兼容的中文周次格式；Android 保存到“下载/执掌东大”并尝试打开系统分享，浏览器直接下载；
- 全校班级/教师/教室课表查询、全部分页和详情网格；
- 网格未发布时从课程列表恢复周次/星期/节次网格。
- 个人数据离线缓存：成功读取后的总览、成绩（含已打开过的成绩分项）、考试安排、个人课表和学期列表会按学号写入应用内部缓存；启动或切换学期时先展示缓存，登录会话有效时再自动刷新并覆盖缓存。
- 登录便捷性：首次进入教务系统时可选择账号密码或微信扫码，并选择是否记住默认方式；内置登录面板中另有手机验证码入口。默认微信时自动进入学校二维码登录页。点击“保存二维码并打开微信”会将登录二维码保存到“图片/执掌东大”，随后只启动微信主界面，用户可在微信“扫一扫 → 相册”中选择刚保存的图片；回到应用后点击“删除刚刚的二维码图片并进入主界面”，应用会删除这张临时图片并自动刷新教务数据。Android 11 及以上已声明微信包可见性，避免已安装微信被误判为未安装。
- Android 首页采用底部五项导航（首页、课表、成绩、考试、更多），返回键优先收起抽屉、弹层和 E 码通展开态；Android 不展示培养方案入口，培养方案功能只保留在桌面浏览器插件中，需让原系统培养方案页面在后台保持打开；
- 桌面插件支持培养方案一键打开原系统查询页，并通过独立的数据驱动渲染器导出 A4 横向 PDF：固定 8 列、课程行语义分页、续页重复表头，不使用浏览器打印，也不带浏览器页眉页脚或个人信息。
- 课程大纲查询属于桌面插件专属功能，读取原系统“培养 → 课程查询 → 课程大纲查询”的完整列表与详情接口；Android 端不显示该入口，也不会伪造移动端接口。

## 构建

```sh
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
export PATH="$JAVA_HOME/bin:$PATH"
./gradlew :app:assembleRelease
```

构建产物位于：

```text
app/build/outputs/apk/release/执掌东大-Android-0.1.87-release.apk
```

根目录的 `dashboard.html`、`dashboard.css`、`dashboard.js` 会在构建前自动同步到 Android assets，因此接口解析和界面逻辑与浏览器插件共用一套代码。

培养方案页的 PDF 导出只按白名单导出方案结构、课组要求、课程明细和必要的完成状态/成绩/学期；不会序列化原始接口对象，因此不会把姓名、学号、账号等身份字段写入文件。Android 不展示培养方案入口，也不会执行这段桌面导出流程。

## 登录持久化说明

应用使用 Android `CookieManager` 持久化学校 WebVPN/统一认证会话，并用 `SharedPreferences` 保存默认登录方式、教务登录标记、缓存索引和 Keystore 加密凭据的密文封装。个人查询结果写入应用内部的 `personal-cache` 目录，文件名是学号的 SHA-256 哈希，不同账号不会共用缓存；设置页可以清除本机缓存。应用重启时先展示缓存，再复用 Cookie 请求最新数据。教务会话过期时，后台认证 WebView 保持页面布局、JavaScript 和重定向运行，但对用户不可见、不接收触摸；直接使用 Keystore 加密凭据打开教务入口重登，不再先复用 E 码通业务会话。认证成功后若学校停在 CAS/WebVPN 中转页，应用会限次重开 `/http/` 与 `/https/` 教务入口验证 Cookie，而不是在未知页面持续轮询。账密提交后若进入设备二次认证页，后台立即停止并提示手动登录。

本地课表覆盖层写入独立的 `local-schedule/` 目录，文件名同样按学号或匿名 profile key 的 SHA-256 哈希生成；写入先落到同目录临时文件，再尝试原子替换，避免半截 JSON 覆盖旧数据。它只保存 `zhizhang-local-schedule/v1` 结构中的本地课程、一次性日程和本地隐藏教务排课键，不保存 Cookie、密码或网络响应；“清除教务缓存”与“清除全部自定义安排”是两个互不影响的操作。

从「更多 / 原教务系统」打开时，应用加载教务首页 `/jwapp/sys/homeapp`，并按实际页面决定是否显示登录层：已经进入教务则只展示原网页和返回按钮；仍停在统一认证页才显示内置登录或原网页账密/二维码。校园网后台重登和「打开原教务系统」的 CAS `service` 必须是 `/jwapp/`（EMAP 换票入口），不能把 `/jwapp/sys/homeapp` 当作回调，否则会带着 ticket 落到 404 页、会话无法生效。带 `ticket=` 的 `/jwapp/` 要等换票完成后再进 homeapp。不要打开 WebVPN 应用根地址（登录后可能落到校园门户或 E 码通）。登录成功后再进入 `/jwapp/sys/homeapp`；未登录时不要把 `/jwapp/` 当作查询台首页（那是 EMAP 欢迎页）。首次打开默认显示内置登录，顶部可切换学校原网页账密或二维码登录；内置登录面板内可进入手机验证码流程，设置页可修改下次默认入口。内置登录仍通过学校官方统一认证页的原表单与 RSA 逻辑提交，不绕过学校的验证、可信设备或访问控制。学校要求图形验证码、手机验证码或账号选择时，应用保留同一个可交互官方认证 WebView，让用户直接完成验证；手机验证码入口由官方模板和官方脚本处理，不在原生层复制学校接口。默认勾选“信任此设备”：成功后把账密写入 Keystore；官方页若提供 `#saveDevice` 则同步勾选（该框在账密页上经常隐藏但仍可操作），没有该节点时不同步、也不改 Keystore 行为。后台重登如果遇到人工验证会立即停止，不会自动发送或重放验证码，而是在主界面底部提示用户手动完成。二维码登录仍通过隐藏但可点击的官方 `#qrcode_login` 标签切到扫码页，与内置账密的信任设备存凭据互不影响。

二维码地址由原登录页的 `QRCode.makeCode` 或其 `checkQRCodeScan` 轮询请求生成，应用只在内存中短暂保存当前二维码地址；点击保存按钮时，从原登录页当前显示的 canvas/img 导出 PNG 到系统相册，不上传二维码，也不把登录地址交给浏览器。二维码本身由学校服务端控制有效期，通常需要在失效前完成扫码。应用回到前台后保留“删除刚刚的二维码图片并进入主界面”按钮，进入查询页时会重新刷新接口数据。

应用不保存明文账号、密码或验证码。用户勾选“信任此设备”且登录成功后，学号和密码会由 Android Keystore 生成的不可导出 AES 密钥以 GCM 模式加密，`SharedPreferences` 仅保存 IV 和密文封装；短信验证码永不持久化。原生网络桥只允许访问 `webvpn.neu.edu.cn`、`jwxt.neu.edu.cn`、`pass.neu.edu.cn` 和 `ecode.neu.edu.cn`，且只注入到本地查询页。设置中可选择自动检测、校园网直连或 WebVPN；校园网使用 `https://jwxt.neu.edu.cn` 与 `https://ecode.neu.edu.cn/ecode/`，校外仍走 WebVPN。

缓存同样不保存 Cookie、Authorization、令牌、验证码或密码字段；只包含已经映射成页面展示结构的成绩、考试、课程、课表和成绩分项结果。用户切换账号后，新账号第一次成功读取会建立新的缓存文件；清除缓存只删除当前账号对应的应用内部缓存。
